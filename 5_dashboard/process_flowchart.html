읽는 법 / 핵심 포인트
  • 회색 박스 (오프라인 빌드) — 대시보드 런타임 밖. 모델링 실험 → ETL → 5_dashboard/data/ 에 parquet/json 으로 한 번 구워둠. 대시보드는 이걸 읽기만 함 (모델을 직접 호출하지 않음).
  • ① FastAPI startup — 서버 켤 때 딱 한 번. parquet 4개 + model/* 을 통째 메모리에 적재하고 status(today/pending/completed)·검사일을 데모용으로 분배. 이후 모든 /api/* 응답은 메모리 DataFrame 필터·집계로 즉답.
  • 분기 ◇ 5개 — q1 위험 시그널? · q2 추가 근거 필요? · q3 데이터 tool 필요? · q4 도메인 지식 필요? · q5 조치 필요? — "아니오" 경로는 모두 위로 합류하거나 종료로 빠짐.
  • 〔LLM〕 + RAG + tool 호출 박스 ★ — 현재 코드의 ChatbotWidget 은 키워드 기반 mock. 이 도식은 Claude API 연동 후 모습으로, 백엔드 오케스트레이터가 기존 데이터 API를 LLM의 tool 로 재사용(⑫·tol) + 도메인 문서 RAG(rag) + 진단 데이터 수집(⑯) 후 narrative 생성(⑰) 까지를 가정.
  • 레이어 색 — 보라=시작/끝, 연보라=프론트 렌더, 민트=프론트→백엔드 API 호출, 파랑=백엔드 처리, 진보라=LLM, 초록=데이터, 노랑=분기.
